# CineTot

A language-learning game that writes riddles you can almost read. It measures
your vocabulary, then generates a description of a film (or a book, an animal,
an invention) using only words you know — plus exactly three you don't.

The three new words are the point. Everything else is scaffolding to make sure
they land.

## Why this is not just a prompt

The obvious version of this app asks a model to "write simply, using these
words". Models do not comply, and nothing checks whether they did. CineTot
treats the model's output as a draft:

1. A frequency-ranked lemma list is built per language from real corpus data.
2. The learner's placement test yields a **frontier rank** — the point where
   their word knowledge falls through 50%.
3. The permitted lemma set is everything inside that frontier, plus words they
   marked known, minus words they marked unknown, plus the three target words.
4. The model writes a draft. Every token is tokenised, lemmatised and checked
   against that set.
5. Words outside it are **named back to the model**, which is asked to replace
   them. Up to two corrections.
6. Anything still outside is shown to the learner in red and made clickable,
   rather than silently passed off as understood.

The verification step is objective, so the loop converges. `test_offline.py`
demonstrates a draft breaking on five words and the next draft leaving none.

## The vocabulary model

**Measurement** is a yes/no (checklist) test in the tradition of X_Lex: six real
words sampled from each of eight frequency bands, salted with ~30% invented
words. Invented words are generated by a character-level Markov chain trained on
the language's own frequency list, then filtered so they are neither real words
nor fragments of real words.

Scoring applies the standard false-alarm correction:

```
corrected = (hits − false_alarms) / (1 − false_alarms)
```

Three honesty checks come out of this and are shown to the learner:

- **false alarm rate** — say yes to everything and the result is flagged
  unreliable rather than silently reported as 30,000 words.
- **consistency** — knowing rare words after missing common ones is not a real
  vocabulary profile. When bands invert, the app says the frontier is the
  number being trusted, not the total.
- **first crossing** — the frontier is fixed at the first band where knowledge
  drops below half. A later band scoring well cannot push the ceiling back out.

**Lemmas, not word forms.** Knowledge is stored per lemma, so knowing *run*
licenses *ran* and *running*; German *gelaufen* resolves to *laufen* (rank 400)
and *Raumschiffen* to *Raumschiff*. Without this, an inflected text reads as
full of unknown words when it is not.

**Interest vocabulary.** Learners name topics; the model proposes domain words;
those are lemmatised, ranked, and put through a short yes/no round. Words they
don't know become the preferred pool for future target selection, so the three
new words per round are words they actually wanted.

**Target selection** draws from a narrow window just past the frontier, weighted
toward its near edge. At a 1,200-word frontier this yields *fantastic, bag,
owner* — not arbitrary rare words from the 8K band.

## Word support

Clicking any word opens a panel combining three sources, each doing what it is
actually good at:

| Source | Supplies |
|---|---|
| `wordfreq` / `simplemma` | lemma, inflection, frequency band, Zipf, rank |
| Wiktionary REST | authoritative sense inventory, part of speech, usage labels (*informal, vulgar, archaic, technical*) parsed into register |
| OpenRouter | explanation written **only in words the learner already has**, plus counter-examples marking the boundary against confusable words |
| Wikimedia Commons / Openverse | freely licensed photographs, keyed on an English query the model produces |

A dictionary that explains an unknown word with three more unknown words is
useless to a beginner. The model is given the ceiling and told to stay under it,
and told never to use the headword's own root.

Image *generation* is deliberately absent: no free image model is dependable,
and for vocabulary work a real photograph beats a plausible painting.

## Layout

Everything is a fixed 1280×820 canvas with `position: absolute`. No breakpoints,
no flex, no grid. The reading surface is styled as a subtitle plate on a dark
screen, which is how you actually read a foreign film.

## Running it

```bash
pip install -r requirements.txt --break-system-packages
cp .env.example .env          # fill in OPENROUTER_API_KEY, pick an ADMIN_EXPORT_PATH
export $(cat .env | xargs)
python app.py                 # http://localhost:5000
```

Two things run without an API key: the placement test and the frequency data.
Riddles and generated explanations need one.

```bash
python test_offline.py        # 11 checks, no key and no network needed
python demo_server.py         # port 5058, model/Wiktionary/Commons stubbed
```

`demo_server.py` runs the real app with only the three network edges replaced,
which is how the UI was verified without live credentials.

### Deploying

Render and Railway both read the `Procfile`. Set `OPENROUTER_API_KEY`,
`SITE_URL`, `SITE_NAME`, `ADMIN_EXPORT_PATH`.

Disk is ephemeral on both. `data/cinetot.sqlite3` survives restarts but not
redeploys — hit `/admin/<ADMIN_EXPORT_PATH>` for a JSON dump first, or mount a
volume. `data/lex/<lang>.json` is a rebuildable cache, not data.

Run **one worker**. `wordfreq` bundles ~57 MB of frequency data and `simplemma`
loads a dictionary per active language; several workers multiply that and will
exhaust a 512 MB free tier. Threads are fine and the `Procfile` uses four.

## Dependencies, and why these

Getting these right is the whole game, so they are pinned and the reasoning is
recorded:

| Package | Version | Why |
|---|---|---|
| `wordfreq` | 3.1.1 | Corpus frequency, 42 languages, data bundled — no network, no API |
| `simplemma` | 2.0.0 | Lemmatiser, 54 languages, pure Python, lazy per-language load |
| `Flask` | 3.1.3 | |
| `requests` | 2.33.1 | |
| `gunicorn` | 23.0.0 | |

**No spaCy.** A model per language is 15–50 MB and three of them will not fit
alongside everything else on a free tier.

**33 languages**, the intersection of the two libraries. This deliberately
excludes Chinese, Japanese and Korean: neither library segments them without
`jieba` or `mecab`, and shipping those is not worth it. Adding a language means
checking it appears in both libraries and adding a line to `config.LANGUAGES`.

## Known limits

- **Proper nouns.** With no POS tagger, a capitalised word absent from the
  frequency list is treated as a name. This works for *Hogwarts*, *Skywalker*
  and *Gandalf*. It fails for *Vader*, which is a genuine rank-16,413 word in
  German (Dutch for *father*), so it is flagged as rare vocabulary instead. The
  cost is an occasional extra retry, absorbed by `LEAK_TOLERANCE`.
- **Frequency lists carry proper nouns.** *Schwerin*, *Porto* and similar
  survive the realness filter and can appear as placement items. A few place
  names in a yes/no test is a known and tolerated artifact of this instrument.
- **CEFR bands are indicative.** They follow commonly cited receptive-vocabulary
  ranges. This is a placement heuristic, not a certification.
- **No accounts.** Learners are a cookie. IP and user agent are stored as weak
  recovery hints, never as the lookup key.
- **`/admin/<path>` is protected only by the secrecy of that path.** Set it to
  something random.

## Adding things

**A quiz domain** is a dict entry in `domains.py` — subject, clue shape,
distractor shape, and what the riddle must not give away. Eight ship: movies,
books, historical events, famous people, songs, video games, animals,
inventions.

**Generation tuning** lives in `config.py`: `TARGET_WORDS_PER_ROUND` (the +3),
`MAX_GENERATION_RETRIES`, `LEAK_TOLERANCE`, `ITEMS_PER_BAND`, `PSEUDO_RATIO`,
`BANDS`.

## Layout of the code

```
app.py              Flask routes
config.py           languages, bands, model preferences, all tunables
lexicon.py          frequency lists, lemmatisation, controlled-vocabulary checking
assessment.py       placement test construction and corrected scoring
pseudowords.py      Markov generator for control items
domains.py          what gets quizzed
db.py               SQLite: learners, profiles, per-lemma knowledge, rounds
services/llm.py     OpenRouter: live free-model discovery, JSON recovery
services/generate.py    the verification loop, word explication
services/dictionary.py  Wiktionary senses and register labels
services/images.py      Commons and Openverse
static/             one HTML file, one stylesheet, one script, no build step
```

`lexicon.py` is the file to read first. Nothing in it involves a model, and
every claim the app makes about a learner's vocabulary is grounded there.
